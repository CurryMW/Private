# 06 — 建立 GitHub 趋势基线

**What to build:** 创建独立的 GitHub 趋势应用与每日快照工作流，通过 GitHub 官方 API 收集 AI 及相邻开发基础设施候选仓库并保存趋势基线。首次运行或缓存丢失时只建立基线，不发送报告，也不伪造增长量。
**Blocked by:** 01 — 建立独立报告应用接缝.
**Status:** integrated — 873b2ec

- [ ] GitHub 趋势拥有独立命令、独立运行结果和独立状态，不复用 AI 情报摘要的发送状态。
- [ ] 每天北京时间 08:45 通过 GitHub 官方 API 获取快照，单次最多保留 200 个候选仓库。
- [ ] 候选范围限定为 AI 与相邻开发基础设施，并排除 fork、已归档、长期不活跃和文档质量不足的仓库。
- [ ] 快照至少保存仓库身份、创建时间、当前 star 数、主要语言、活动与质量判断所需信息以及采样时间。
- [ ] 首次运行只建立趋势基线，明确返回“已建立基线”结果，不发送钉钉消息。
- [ ] 状态通过工作流缓存跨运行保存，不提交数据库或专用状态分支。
- [ ] 缓存丢失、损坏或不兼容时重新建立基线并顺延报告，不把当前 star 数当作 72 小时增长量。
- [ ] GitHub API 失败或快照不完整时显式失败，且不覆盖最后一份有效基线。
- [ ] 高层测试使用伪造 GitHub API 和临时状态覆盖首次基线、正常更新、缓存丢失与 API 失败。
