# 07 — 发送 72 小时 GitHub 趋势报告

**What to build:** 基于连续有效快照计算真实的 72 小时趋势，并每隔 72 小时发送一次独立钉钉报告。报告优先展示 3 个增长动量项目和 2 个新兴项目，star 增长只用于召回，最终仍需通过 AI 相关性和项目质量门槛。
**Blocked by:** 04 — 验证并接入唯一生产模型; 06 — 建立 GitHub 趋势基线.
**Status:** integrated — `43d2c23`

- [x] 存在有效对比基线时，首份报告以初始基线已满连续 72 小时为准；后续报告以距上一次成功报告已满连续 72 小时为准，不能以自然日或固定星期代替观察周期。
- [x] 增长动量项目按真实 72 小时 star 增量召回，最多选择 3 个通过 AI 相关性与质量门槛的仓库。
- [x] 新兴项目限定为创建不超过 90 天，并结合 72 小时 star 增量与增长比例召回，最多选择 2 个。
- [x] 报告总数最多 5 个；候选不足时允许少发，不用低质量项目补齐名额。
- [x] 每个项目展示用途、入选原因、当前 star、72 小时增量、主要语言和 GitHub 链接。
- [x] 报告发送到与 AI 情报摘要相同的钉钉群，但使用可清晰区分的标题与独立状态。
- [x] 未满 72 小时、首次基线或缓存重建时不发送消息，也不推进上次成功报告时间。
- [x] GitHub API、模型或钉钉失败会使本工作流失败，不影响 AI 情报摘要，也不写入成功报告状态。
- [x] 只有报告成功发送后才更新上次成功报告时间与后续比较基线。
- [x] 高层测试覆盖 72 小时边界、两类榜单、候选不足、失败重试以及两个报告状态互不干扰。
